### ログイン

```text
目的：本人であることを確認し、本人だけが会員向けの機能・情報を使えるようにする
条件：メールアドレスの状態とパスワードの状態

・ログイン
　├画面遷移
　　　└ホーム画面の「ログイン」を押下すると、ログイン画面（https://hotel-example-site.takeyaqa.dev/ja/login.html）に遷移する
　├表示
　　　├見出し「ログイン」、ラベル「メールアドレス」「パスワード」と、それぞれの入力欄が表示される
　　　└「ログイン」ボタンにマウスホバーすると、グレー文字・黒背景から白文字・グレー背景に変わる
　├入力ルール
　　　└必須
　　　　　├メールアドレス
　　　　　└パスワード
　└正常系
　　　└登録済みのメールアドレスとパスワードを入力して「ログイン」を押下すると、マイページに遷移し、緑色の「ログアウト」ボタンが表示される

・異常系
　├入力チェック（その欄だけで決まる）
　　├メールアドレス：空→「このフィールドを入力してください。」が表示され、入力欄が赤枠になる
　　├メールアドレス：形式不正→「メールアドレスを入力してください。」が表示され、入力欄が赤枠になる
　　└パスワード：空→「このフィールドを入力してください。」が表示され、入力欄が赤枠になる
　└認証（メールアドレスとパスワードの組み合わせで決まる）
　　├登録済みのメールアドレス ＋ 間違ったパスワード→「メールアドレスまたはパスワードが違います。」が表示され、入力欄が赤枠になる
　　└未登録のメールアドレス ＋ 空以外のパスワード→「メールアドレスまたはパスワードが違います。」が表示され、入力欄が赤枠になる
```

### 会員登録

```text
目的：ユーザーが自分の情報を登録して会員になり、会員向けの機能（ログイン・会員限定プラン・マイページ）を使えるようにする

・会員登録
　├画面遷移
　　　└ヘッダーの「会員登録」リンクを押下すると、会員登録画面（https://hotel-example-site.takeyaqa.dev/ja/signup.html）に遷移する
　├入力ルール
　　　├必須
　　　　　├メールアドレス
　　　　　├パスワード（8文字以上）
　　　　　├パスワード（確認）（パスワードと一致）
　　　　　└氏名
　　　└任意
　　　　　├会員種別（初期値：プレミアム会員）
　　　　　├住所
　　　　　├電話番号（11桁の数字）
　　　　　├性別（初期値：回答しない）
　　　　　├生年月日
　　　　　└お知らせを受け取る
　└正常系
　　　├必須4項目のみ入力して「登録」を押下すると、マイページに遷移する
　　　├全項目を入力して「登録」を押下すると、マイページに遷移する
　　　└プレミアム／一般のどちらでも登録できる

・異常系
　├必須項目の未入力
　　　├メールアドレス未入力で「登録」→「このフィールドを入力してください。」が表示される
　　　├パスワード未入力で「登録」→ 同上
　　　├パスワード（確認）未入力で「登録」→ 同上
　　　└氏名未入力で「登録」→ 同上
　├メールアドレス
　　　└形式が不正（例：@なし）で「登録」→ 「メールアドレスを入力してください。」が表示される 
　├パスワード
　　　└7文字で「登録」→ 「8文字以上で入力してください。」が表示される
　├パスワード（確認）
　　　└パスワードと不一致で「登録」→ 「入力されたパスワードと一致しません。」が表示される
　├電話番号
　　　├10桁で「登録」→ 「指定されている形式で入力してください。」が表示される
　　　├12桁で「登録」→ 同上
　　　└半角数字以外を含めて「登録」→ 同上
　└登録済みのメールアドレス
　　　└同じメールアドレスで再登録 → 「このメールアドレスはすでに登録済みです。」が表示される👈ログイン画面では登録済みかどうかをぼかしているのに、ここでは教えてしまっている。力技で登録されているアドレスを割り出せてしまうのでは？🤔
```

```text
　　　└「アイコン設定」「退会する」ボタンが表示される

　　　　└お知らせを受け取るにチェック入らない場合→受け取らないと表示される。

・異常系
　└未ログイン状態でマイページのURL(https://hotel-example-site.takeyaqa.dev/ja/mypage.html)を直接開くとホーム画面に遷移する
```

### 宿泊料金の計算

```text
目的：選んだ条件どおりの正しい合計金額で予約を申し込める
条件：プラン・宿泊日の曜日・宿泊数・人数・追加プラン

・観察（基準：素泊まり・平日・1泊・1人・追加なし）
　├基準 → 合計 5,500 円
　├曜日を土日に変える → 合計 6,875 円（基準との差 25%アップ）
　├曜日を金曜に変える → 合計 5,500 円（平日扱い）
　├泊数を2泊に変える → 合計 11,000 円（基準の2倍）※土日を含むと2倍にならない
　├人数を2人に変える → 合計 11,000 円（基準の2倍）
　├朝食バイキングを追加 → 合計 6,500 円（基準との差 +1,000）
　├昼からチェックインプランを追加 → 合計 6,500 円（基準との差 +1,000）
　├お得な観光プランを追加 → 合計 6,500 円（基準との差 +1,000）
　├朝食バイキング・2泊・1人 → 1,000 × 1人 × 2泊 が加算される
　├朝食バイキング・1泊・2人 → 1,000 × 2人 × 1泊 が加算される
　├昼からチェックインプラン・2泊・1人 → 合計 12,000 円
　└お得な観光プラン・2泊・1人 → 合計 12,000 円



・見つけたルール👈ソースコード(src/lib/billing.js)で裏取り
　├基本料金 → 単価 × 人数 × 泊数
　├土日の料金 → 土日の泊は単価が25%アップ（金曜は平日扱い）
　└追加プランの料金
　　├朝食：1,000円 × 人数 × 泊数
　　└昼からチェックインプランとお得な観光プラン：1,000円 × 人数
```

## 3. 優先度

優先度は、影響度と起きやすさを高＝3・中＝2・低＝1として掛け合わせた点数が高い順とする。
同点の場合は、誤りが表示されても一見正しく見えるなど、誤りに気づきにくい機能を優先する。

```text
# ログイン
影響度：高
理由：入れないと会員機能が全て使えないないが、一般プランなら予約できる
起きやすさ：中
理由：条件は2つ（メール・パスワードの状態）だが、組み合わせで結果が分かれる

# ログアウト
影響度：中
理由：共用端末で他人に使われるリスクがある
起きやすさ：低
理由：操作はボタン1つで、条件がない

# 会員登録
影響度：高
理由：登録できないと会員機能が全て使えない
起きやすさ：中
理由：入力ルールが多い（8文字以上・一致・11桁）が、各ルールは単純

# マイページ
影響度：低
理由：表示のみで、操作に影響しない
起きやすさ：低
```

## 4. 最優先の機能

最優先は「宿泊料金の計算」とする。

## 5. 気づき

- 登録済みのメールアドレスで「このメールアドレスはすでに登録済みです。」と表示される件は、サイトの動き（テストベース1）と公式e2eの期待値（テストベース2）が一致しているため、仕様として受け入れ、今の動きを期待結果とする。
ただし、本番のサイトであれば登録済みのメールアドレスを第三者に知られるリスク（アカウント列挙）があるため、分析に「気づき」として書き残す。
- ログアウト後に「戻る」でマイページが見える件は、ブラウザが直前の画面を表示しているもので、リロードするとホーム画面に戻ることから、サイトのログイン状態の確認は機能していると判断し、仕様として受け入れる。
ただし、本番のサイトであれば共用端末で個人情報を見られるリスクがあるため、分析に「気づき」として書き残す。
