## 全体
テスト設計の 18 件をすべて自動化し、くり返し実行しても安定して通る状態にできている。特に良い点は次の3つ。

- 「たまたま通る」に気づいた：人数-02 の失敗から、合計は欄から離れたとき（change イベント）に計算されると突き止め、ほかの 7 件も初期値と同じ値だったから通っていただけだと気づいて、全件で Tab を押す形にした。
- 原因を調べてから直した：チェックボックスを押せない原因を、カレンダーがかぶさっていることだと確かめてから、Escape で閉じる対応にした。
- 外の部品を基準で選んだ：祝日は国が決めるため自分では計算せず、「ルールが変わったときに更新されているか」などの基準でパッケージを選び、確認のルール（毎年2月ごろ）まで決めた。

## 1. テストコード
- 1-1：テスト名の書き方がそろっているか？ 曜日-01〜05・人数-02・追加プランは「直近の月曜から」、宿泊数-02〜04 は「月曜から」になっている。
- 1-2：`toContainText('5,500円')` は「5,500円 を**含む**」かを確かめる。もし実際の合計が `15,500円` だったら、このテストはどうなるか？
- 1-3：18 件すべてに、最初の 3 行（プラン一覧の部品を作る → 予約画面を開く → プラン名を待つ）がある。もしプラン名を待つ方法を変えることになったら、何か所を直すことになるか？
- 1-4：`nearestWeekdayHoliday` の while は「平日の祝日が見つかるまで」進む。もしパッケージのデータが切れた年（2051年〜）に実行したら、どうなるか？ また、見つかった祝日が宿泊日に選べる範囲（明日〜90日後）を超えていたら？

## 2. テスト設計書（6. 実装の方針）
- 2-1：理由に「（基準④）」とある。基準④は「手動に残す」かを決める基準。POM を入れる理由として、この書き方で読む人に伝わるか？
- 2-2：「Tab と Escape を足したときも、直したのは fillStay だけで、18件のテストは修正せずに済んだ」とある。Tab を入れたときのコミット（950b1e9）では、何が変わったか？
- 2-3：3 行の理由が、改行だけでつながっている。Markdown で表示したとき、どう見えるか？

## 指摘への対応方針（ユーザー回答）

| # | 指摘 | 対応方針 |
|---|---|---|
| 1-1 | テスト名の「直近の」の有無がそろっていない | 反映：docs/test-design.md の書き方に合わせて「月曜から」にそろえる（設計書で「直近の平日の祝日から」としている曜日-05 はそのまま） |
| 1-2 | `toContainText` だと「15,500円」でも「5,500円」のテストが通る | 反映：`toHaveText` にする（間違った金額でもテストが通ってしまうリスクがあるため） |
| 1-3 | 18 件すべてに同じ 3 行（プラン名を待つ行を含む）がある | 反映：プラン名を待つ行を PlansPage の openReserve にまとめ、テスト側から消す（理由は下） |
| 1-4 | 祝日のデータが切れると while が止まらない／見つかった祝日が 90 日後を超えると選べない | 見送り：平日の祝日どうしの間が90日を超えることは今のところまずなく、2051年以降の祝日がなくなる問題も、毎年2月の確認で翌年分を比べるため2050年2月に気づけることから、今は対応せず見送る。 |
| 2-1 | POM の理由の「（基準④）」は、手動に残すかを決める基準を指している | 反映：「（基準④）」を消し、「基準④と同じく、保守の手間を小さくする考え方。」と書く（基準④は自動化するかを決める基準、POM はコードの形を決めたことで、種類がちがうため） |
| 2-2 | 「Tab と Escape を足したときも…18件のテストは修正せずに済んだ」が事実とずれている | 反映：Tab のときは fillStay を作ってテスト8件を書き換え、Escape のときは fillStay の中だけを直してテストは変えずに済んだ、と事実のとおりに書き直す |
| 2-3 | POM の理由の 3 行が改行だけでつながり、表示すると 1 段落になる | 反映：理由を箇条書きにする（設計書のほかの箇所でも箇条書きを使っていて、書き方がそろうため） |

### 1-3 の理由（ユーザー回答）
- 予約画面は新しいタブで開き、読み込みが終わる前に入力すると失敗することがあるため、プラン名が表示されるまで待つ処理が必要になる。
- この待ち合わせは「予約画面を開く」操作の一部と考え、openReserve の中にまとめた。
- これにより、18件のテストから同じ処理を消せたうえ、今後テストを増やすときも待ち合わせを書き忘れる心配がなくなった。
