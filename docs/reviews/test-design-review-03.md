# テスト設計 レビュー（第3回）

- 日付：2026-10-31
- 対象：[docs/test-design.md](../test-design.md)（4. 自動化の判断基準、5. テストケースごとの自動化の判断）
- レビュアー：Claude（ベテランQAエンジニアの立場で助言）

## 全体
自動化の判断基準を、自分の手動 QA の経験から言葉にできている。特に良い点は次の3つ。

- 経験から基準を作った：「速度の計測は人がやると誤差が出る」「条件をそろえて○×をつける繰り返しがつらい」「期待値が間違っているときは今の動きを書いていた」という経験を、それぞれ基準①②③にした。
- 当てはめて基準を見直した：曜日-05（直近の平日の祝日）に当てはめたとき、①〜③だけでは足りないことに気づき、費用対効果の基準④を足した。
- 数字で天秤にかけた：曜日-05 を「祝日一覧の更新は年1回・1時間程度」「手動は実行のたびに毎回」と比べて判断した。

## 1. 自動化の判断基準
- 1-1：基準どうしがぶつかったときはどうするか？ たとえば、①②には当てはまる（自動化する）が、④にも当てはまる（手動に残す）テストがあったら、どちらを優先するか。テスト分析で優先度の「組み合わせのルール」を決めたことを思い出す。
- 1-2：基準①と②の理由は、どちらも「同じ精度で」で終わっている。①と②の違いは何か？ 読む人が「同じことを2回言っている」と感じないか。

## 2. テストケースごとの自動化の判断
- 2-1：「基準」の列の書き方。曜日-05 は「①②④」となっているが、④は「手動に残す」の基準。曜日-05 は④に**当てはまらなかった**から自動化した。この書き方で、読む人に伝わるか？ また、1行目の理由には③（期待値がはっきりしている）のことも書いてあるが、列は「①②」になっている。
- 2-2：手動に残すテストが 0 件になった。それ自体は問題ではないが、面接官は「全部自動化するのか？ 手動テストの役割は？」と聞きたくなるかもしれない。0 件になった理由を書いておくか？

| # | 指摘 | 対応方針 |

| 1-1 | 基準どうしがぶつかったときのルールがない | 反映：「基準③④に当てはまる場合は、①②に当てはまっていても自動化しない（③は品質を担保できないため。④はリソースを無駄にするため）」を足す |
| 1-2 | 基準①と②の違いが分かりにくい | 反映：②の理由の後半を「自動テストは、何回実行しても、疲れたり慣れたりしないため、結果が信頼できる」に書き直す（①は「再現できる」、②は「結果が信頼できる」で分ける） |
| 2-1 | 「基準」の列の書き方 | 反映：曜日-05 の基準を「①②」にする。列には当てはまった基準だけを書く（④で天秤にかけたことは理由の列に残す） |
| 2-2 | 手動に残すテストが 0 件の理由 | 反映：「今回のテストケースは、すべて期待値がはっきりしたものであったため。操作感のように、期待値を決めにくいテストは、手動に残す対象になる」を足す |

### レビュー中に出た論点
- 基準①〜④のどれにも当てはまらないテストをどうするか → 今回の 21 件には該当なし。当てはまらないテストが実際に出てきたとき（ほかの機能の設計など）に決める。
